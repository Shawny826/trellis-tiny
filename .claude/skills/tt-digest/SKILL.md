# Digest old material

Old tasks and journals are evidence, not rules. Turn the parts that still hold into specs, and leave the rest where it is.

1. Agree on the scope with the user: one topic, one task, or a short list. Don't sweep everything at once. Skip material already marked as digested unless the user asks for it again.
2. Read the material. For an upstream task, that is its `prd.md`, its research notes, and the journal entries about it.
3. Check each claim against the current code. Keep only what is still true and still matters for future changes.
4. Write what survives with `tt-record`, linking to the source material so it can be found later.
5. Mark what you processed. For an upstream task, append ` — digested into [file](file) on YYYY-MM-DD` to its line in `.trellis/spec/upstream-tasks.md`, or ` — digested, nothing kept, on YYYY-MM-DD` when nothing survived. That file was generated by the migration, so marking it leaves the material itself untouched.
6. Report to the user what you recorded, what you dropped as outdated, and anything that conflicts with the current specs. Leave conflicts for the user to decide.

Don't move, rewrite, or delete the old material.
